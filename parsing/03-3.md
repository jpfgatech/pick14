# Parsing: 03-3 feature-based Q analysis (resimulation, pre-draw snapshots)

## Goal

Project each game snapshot onto a 7-element summary feature vector and
correlate with N+1 point-gap.  Unlike the 03-1 data, snapshots here are taken
**before** the stochastic draw so they reflect only the deterministic action
outcome.

## Simulation design

Use `apply_match(immediate_draw=False)` and `apply_play(immediate_draw=False)`
(the new sim_core deferred-draw API) to pause state before the deck draw.

  A (match)  — after `apply_match(immediate_draw=False)`: matched cards moved
               to score pile, DRAW1 not yet applied.  Hand may have 0–2 cards.
  A (pass)   — after `apply_pass_match`: hand and public unchanged.  3 cards.
  B1 (play on pass turn) — after `apply_play(immediate_draw=False)`: discard
               applied, DRAW2 not yet applied.  2 cards in hand.
  B2 (play on match turn) — after `apply_play` (default): discard applied, no
               DRAW2 on match path.  3 cards in hand.

**Analysis snapshot kinds (three categories):** the script and plots aggregate
as:

1. **A (match)** — pre-DRAW1 after a match.
2. **A (pass)** — after a pass, before PLAY.
3. **B (play)** — B1 and B2 together (any post-play, pre- or post-DRAW2 state
   as defined in `simulate_game`: B1 = play after a pass, B2 = play after
   match, no second draw on that path).

After each snapshot, the deferred draw is completed with
`apply_post_match_draw` / `apply_post_pass_draw` before the next player moves.
If the game ends during the final discard (`is_finished` is true at DRAW2), we
skip `apply_post_pass_draw` — the game is already over.

### Why this matters

The 03-1 snapshot A (match path) was taken *after* DRAW1, giving the player
4 cards in hand.  That mixed the known action outcome with one random card draw.
Pre-draw snapshots isolate the deterministic consequence of the action.

## The 7 summary features (raw — no /7 or /18)

Features are stored **unscaled** (integer counts, raw `Σ (occ/4)` for f5, raw
**score points** 0‥**18** for f6/f7) so off-by-one and scaling issues are
easy to see in data and on plots.

Computed from the **actual Card** objects at snapshot time.  No theoretical
deck-max tables are used for f6/f7.

| id | Name | Definition |
|----|------|------------|
| f1 | distinct subset-sums | Count of **distinct** non-empty subset `game_value` sums of the hand. |
| f2 | distinct sums < 14 | Count of those distinct sums that are < 14.  f4 = f2. |
| f3 | known match categories | Count of sums s with s < 14, complement c = 14−s in {1,…,13}, and at least one public card of value c. |
| f5 | option density | Sum over **known** categories of `(public occurrences of c) / 4`.  Unbounded (e.g. fives + joker bucket). |
| f6 | best match score (pts) | Over known categories, max of (best `score_value` over hand combos for s) + (best public at c).  **Raw points 0‥18**. |
| f7 | second-pub match score (pts) | Like f6 but second-best public at c, or 0 if < 2 public cards of c.  **Raw points 0‥18**. |

## Outcome

N+1 gap = `pts[p, j+1] − mean_q pts[q, j+1]`

where j is the current match-turn index and j+1 is the next match turn for
the same player p.  Snapshots where any player lacks a j+1 turn are discarded.

## Plots and outputs (`artifacts/03-3/`)

| File | Content |
|------|---------|
| `features.png` | N+1 gap vs each feature, **all** snapshots.  x = **discrete** distinct feature values; **no** width binning.  Solid = mean gap; band = 25–75 %; dashed = 5/95 %. |
| `feature_frequencies.png` | **Frequency** of each distinct value: bar height = count; tick label = value and proportion `p = count / N` so sparse levels are obvious. |
| `features_by_category.png` | Same gap-vs-value curves, split into **three 2×4 blocks** (A match, A pass, B play) so composition effects are visible. |
| `log.txt` | Ranges, Pearson r, per-kind sample counts, gap at min/max *distinct* x (not arbitrary bins). |
