# Parsing: 03-3 feature-based Q analysis (resimulation, pre-draw snapshots)

## Goal

Project each game snapshot onto a 7-element summary feature vector and
correlate with N+1 point-gap.  Unlike the 03-1 data, snapshots here are taken
**before** the stochastic draw so they reflect only the deterministic action
outcome.

## Simulation design

Use `apply_match(immediate_draw=False)` and `apply_play(immediate_draw=False)`
(the new sim_core deferred-draw API) to pause state before the deck draw.

  A (match)  — after `apply_match(immediate_draw=False)`: matched cards moved
               to score pile, DRAW1 not yet applied.  Hand may have 0–2 cards.
  A (pass)   — after `apply_pass_match`: hand/public unchanged.  3 cards.
  B1 (play on pass turn) — after `apply_play(immediate_draw=False)`: discard
               applied, DRAW2 not yet applied.  2 cards in hand.
  B2 (play on match turn) — after `apply_play` (default): discard applied, no
               DRAW2 on match path.  3 cards in hand.

After each snapshot, the deferred draw is completed with
`apply_post_match_draw` / `apply_post_pass_draw` before the next player moves.
If the game ends during the final discard (`is_finished` is true at DRAW2), we
skip `apply_post_pass_draw` — the game is already over.

### Why this matters

The 03-1 snapshot A (match path) was taken *after* DRAW1, giving the player
4 cards in hand.  That mixed the known action outcome with one random card draw,
conflating the player's decision with luck.  Pre-draw snapshots isolate the
deterministic consequence of the action.

## The 7 summary features

Features are computed from the **actual Card objects** present at snapshot time.
No theoretical deck-max tables are used.

### f1 — column validness summary
  total unique hand subset-sums / 7
  "How rich is the hand in distinct subset combinations?"

### f2 — unique sum summary
  unique sums < 14 / 7
  "How many partial sums can contribute to a 14-sum match?"

### f3 — known category summary
  count_known_cats / 7
  A sum s is a known category if s < 14 AND the complement (14−s) is present
  in the public pool.
  "How many distinct digit combos can match right now?"

### f4 — potential category summary
  = f2  (every sum s < 14 has a valid complement in [1,13])
  "How many digit combos could eventually match?"

### f5 — number of options summary
  For each known category (complement c, occ public cards of digit c):
    column value = occ / 4
  Summary = (sum of column values) / 7
  Note: no `min(occ, 4)` clamp; occ / 4 > 1 is possible for c = 5 (up to 6
  physical cards of game_value 5).  See instructions/03-3.md for the debate.

### f6 — max points summary (actual cards)
  For each known category:
    best_hand_pts = max score_value sum over all hand subsets summing to s
    best_pub_pts  = max score_value among actual public cards of game_value c
    column = (best_hand_pts + best_pub_pts) / 18
  f6 = max over all known categories.
  Uses ACTUAL card suits, not deck-level theoretical maxima.

### f7 — second points summary (actual cards)
  Like f6 but using the second-highest score_value among public cards of c.
  0 if fewer than 2 public cards of that complement.

## Outcome

N+1 gap = pts[p, j+1] − mean_q pts[q, j+1]

where j is the current match-turn index and j+1 is the next match turn for the
same player p.  Snapshots where any player lacks a j+1 turn are discarded.
