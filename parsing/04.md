# Parsing: 04 Decision-tree size and timing

## Goal

Measure how large the **player-decision** game tree is for a single fixed-deck
game.  All analysis is in `scripts/04_decision_tree.py`.  (Optional: per-checkpoint
deck reshuffles; off by default.)

## Design

### Fixed-deck DFS

- A **fixed RNG seed** produces a fixed deck order.  Draws (DRAW1, DRAW2) are
  resolved inline — no branching.
- Branching is only over **player** choices: legal moves at MATCH and PLAY.

**Single match vs pass is not a branch:** if
`legal_moves` is **exactly** one :class:`MatchMove` and one
:class:`PassMatch` (two options total), we **do not** explore pass — we always
take the match, same as a single forced move.  That removes a very common
2-way fork that the instruction set treats as a fixed policy (match when you
can).

- At each state:
  1. Resolve `skip_empty_hands` and any DRAW1/DRAW2 in-place.
  2. `moves = legal_moves(state)`.
  3. If the single match + pass case: apply the match, recurse — **no
     checkpoint.**
  4. If one move: apply, recurse.
  5. Else: **checkpoint** — clone and recurse for each `move` in `moves`.

- **Node limit** (default 200,000) stops the DFS early.

#### Decision table (after the rule above)

| Situation | Checkpoint? |
|-----------|--------------|
| Forced pass (no match) | no |
| Exactly one match + pass | **no** (forced match) |
| 2+ distinct matches, ± pass | yes, branch on each listed move |
| PLAY, 1 card | no |
| PLAY, 2+ cards | yes, branch on each discard index |

The script defaults to **`--player-counts 4 2`**: it runs a fixed-deck DFS for
**4 players** and **2 players** on the same seed for comparison.  (2 players
does **not** always shrink the tree; see Findings.)

### Optional: N reshuffle branches

If `--max-reshuffles` > 0, each run also tests N=1,…,K extra deck orderings at
checkpoints.  **Default 0** (fixed deck only).

### Timing

- **Single-pass baseline**: one game, greedy match + caution play, counts
  **“real”** path checkpoints (same “not 1 match + pass” rule).
- **DFS time**: until node limit; dominated by `clone_state`.

## Output

`artifacts/04/log.txt` — text for each `player count` in `--player-counts`.

## Findings (n_hand=3, seed=42, node\_limit=200k, N=0)

### Match+pass policy impact (4p)

With the old rule (branch on every ≥2 legal moves), the first 200k nodes saw
~37k checkpoints.  **After** collapsing 1 match + pass, the same cap sees
**~23.4k** checkpoints — a large drop because most binary “match or pass”
decisions are removed.

| Metric (4p) | Single-pass path | In first 200k DFS nodes (N=0) |
|-------------|-----------------|------------------------------|
| Real checkpoints (path) / seen in DFS | 39 | 23,441 |
| Mean children per checkpoint (DFS sample) | — | **3.15** (was ~2.66 before the rule) |
| Est. full-tree size (geometric from sample) | — | **10^11,348** (was ~10^15,118 before) |

(Exponent is a rough product of branch counts; it is for order-of-magnitude
only.)

### 2p vs 4p (same seed)

| | 4p | 2p |
|-|----|----|
| Single-pass: decisions | 63 | 61 |
| Single-pass: real checkpoints on path | 39 | 39 |
| DFS checkpoints in 200k nodes | 23,441 | **31,794** (more) |
| Mean branch factor at checkpoints | 3.15 | 2.91 |
| Est. 10^exponent (same crude formula) | 10^11,347.7 | **10^14,317.8** (larger) |
| Time to 200k nodes | ~28 s | ~34 s |

**2p is not a smaller tree** in this run: fewer players means **more** turns
per player over the same deck, different public-pool history, and the sampled
search hits **more** checkpoints and a **higher** rough exponent.  “Smaller
player count” is not a simplification of the *decision* tree in general.

### Conclusions (unchanged in spirit)

1. The full tree is still astronomically large even with no pass-vs-single-match
   branching and with only 4 or 2 players.
2. **Clone cost** of `RlPick14State` is the main DFS bottleneck.
3. On-policy or value-based methods (03-x) remain the practical approach.
