`1` — current draft.  Bump when field names or semantics change.

## One game run

```jsonc
{
  "schema_version": 1,
  "seed": 42,
  "n_players": 4,
  "n_hand": 3,
  "explorer_seat": 0,
  "policy": { "match": "greedy_stingy", "play": "caution" },
  "single_match_forced": true

```

## Fork event (explorer checkpoint on the main stem)

```jsonc
{
  "fork_id": 7,
  "main_step": 7,
  "phase": "match",
  "explorer_seat": 0,
  "legal_branches": [
    { "branch_id": 0, "move_kind": "match", "public_index": 2, "hand_indices": [0, 1] },
    { "branch_id": 1, "move_kind": "play", "hand_index": 0 }
  ],
  "stem_branch_id": 0
}
```

(`move_kind` and payload must match the actual `legal_moves` encoding used in
code — hash or string key is fine as long as it is **stable** between stem and
alts.)

## Per-branch, per-layer snapshot (the “right data” for a future good/bad test)

`layer` is 0, 1, or 2 after the **forking** alternative (see `instructions/04-1`):

- `layer` **0** — immediately after applying that branch’s first move and
  resolving any forced draws that follow the rules.
- `layer` **1** — after following the **main** policy for all non-explorer
  moves and the explorer’s **on-policy** resolution **once** at their *next*
  checkpoint, from the `layer-0` state; then snapshot.
- `layer` **2** — same, one more explorer checkpoint cycle, then **truncate**
  the branch (no more layers).

```jsonc
{
  "fork_id": 7,
  "branch_id": 1,
  "layer": 0,
  "truncated_after_layer": true,
  "per_player_total_score": [12, 5, 5, 4],
  "n_plus_one_gap": null
}
```

- `n_plus_one_gap` may stay `null` until the 03-3 **same** point-gap
  definition is wired; once set, it is the scalar aligned with 03-3.
- `per_player_total_score` is always the **sum of `score_value` over
  `score_piles[p]`** at that snapshot, order `[p=0,…,P-1]`.

**Stem vs alts** — same rows for `branch_id` = `stem_branch_id` and for every
**alternative**; a future “good decision” can compare, e.g.
`n_plus_one_gap[stem, layer] - n_plus_one_gap[alt, layer]` (sign convention
TBD).

## Size / feasibility

- Forks on stem are rare compared to 04-DFS: **O( ∑_forks (K_f × 3) )** snapshots
  for K_f legals, three layers, one explorer, versus exponential full tree.
