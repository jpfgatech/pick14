# Definition of Game Turns, States and Target


We assume two player game.

## Initial State

The game shall have a initial state, state[0, 1], not state[0, 0]. we explain later
state[0, 0] has 3 initial hand cards for each player, one initial public card, and empty score pile for everyone

At state[0, 0], the state tensor should look like

player score pile is empty for the last three turns
opponent score pile is empty for the last three turns
player hand card is recorded
the initial public card is allocated to opponent view of the public pool, i.e. opponent_public[t-1]
the rest of the public pool rows, player or opponent, are all zero

## Player state

player state are encoded as state[round, player seat], or [round, turn]
for a two player game, round goes from 1 to up to roughly 24, and turn iterates between

The player begins with the last turn from the opponent, state[round, turn-1], or state[round, N-1] if turn == 0 for a N player game
Which is also why the initial state is encoded as state[0, 1].
Because player 0 is about to act, and it assumes that the initial state is the output after player 1's action
We transfer from state[round, turn] to state[round + (turn+1)/N, (turn+1)%N]
The new state is the state AFTER the action of the player in SEAT (turn+1)%N
e.g. state[0, 1] -> (player 0, round 1) state[1, 0] -> (player 1, round 1) state[1, 1] -> ...

The cards that the player just matched, and the card the player just played, should appear in his side of the state tensor
and be part of the input to the next player's pre-action state
The next player q network shall look at the state tensor UPDATED BY THE ENVIRONMENT based on legal actions and traversal/random draw & play, and evaluate its own state

The new state also involves random draw.
There is only one sate per turn, unless we adopt counterfactual data augmentation
This is consistent with the state projection strategy described in 05.md

The network will look at the outcome state of possible actions, and evaluate its quality.


## Evaluating States

A state is evaluated based on its FUTURE

e.g. for the state[round, turn], the action of that player, seat {turn}, of {round} may have scored points for it self
Those points are not to be projected from the state[round, turn]

instead, after state[A, B], we record the next four turns:
e.g. since state[1, 0], after the initial action of player 0
player 1 scores P[1, 1] in round 1, turn 1
player 0 scores P[2, 0] in round 2, turn 0
GAP 1 = P[2, 0] - (P[1, 1] + P[2, 0]) / 2

player 1 scores P[2, 1] in round 2, turn 1
player 0 scores P[3, 0] in round 3, turn 0
GAP 2 = P[3, 0] - (P[2, 1] + P[3, 0]) / 2

The network is expected to predict:
GAP1 + 0.9 * GAP2 + 0.9^2 * GAP3 ... until the window size

Similarly, 
e.g. since state[0, 1], the initial state of the game
player 0 scores P[1, 0] in round 1, turn 0
player 1 scores P[1, 1] in round 1, turn 1
GAP 1 = P[1, 1] - (P[1, 1] + P[1, 0]) / 2

player 0 scores P[2, 0] in round 2, turn 0
player 1 scores P[2, 1] in round 2, turn 1
GAP 2 = P[2, 1] - (P[2, 1] + P[2, 0]) / 2

The network is expected to predict:
GAP1 + 0.9 * GAP2 + 0.9^2 * GAP3 ... until the window size

Since we define the window to be 2 rounds, the series ends at GAP2
