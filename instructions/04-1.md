# Side-branch evaluation (limited lookahead, not full backtrack)

## Motivation

Full decision-tree search (`instructions/04.md`) is infeasible.  Instead of
backtracking to the *last* match/play checkpoint, we **do not** rewind the main
line.  We run the game **forward** on a **main stem** (one long on-policy
simulation).  Whenever the **designated explorer** faces a *real* choice, we
**clone**, try **alternative** first moves, and extend each **side branch** only
for a **short fixed horizon** (e.g. two *explorer* decision layers).  The branch
is then **cut**; we read off scores and discard the clone.  The main stem never
jumps back.

This is **side-branch evaluation**, not backtracking in the “undo the game
clock” sense.

## Who acts how

- **Explorer** (one fixed seat, e.g. player 0): at each of *their* checkpoints
  we may evaluate alternatives off the current stem.
- **Everyone else, always** on the same policy as today (e.g. greedy match +
  caution play on that clone).  No branching for non-explorers.  (If a
  non-explorer has multiple legal moves, we still resolve them with the fixed
  policy so their choices are *deterministic* given the public policy, not
  second-class citizens with two threads.)

- **Match vs single pass:** the same “always match when the only other option is
  pass” rule as in `04` is recommended so fork points are only *genuine* choices.

## Horizon (“two rounds” / “two steps”)

Precise meaning (agreed for data collection):

- **Root fork:** explorer has ≥ 2 legal moves; stem = policy; **alternatives** =
  other legals (or all legals, with stem as one labeled branch — choose one
  convention and stick to it).
- **Layer 0 (immediate):** after applying the **alternative** (and the usual
  forced Draw1/Draw2 resolution), **record** a score snapshot.  (Optional: this
  is “after 0 *explorer* follow-up decisions”.)
- **Layer 1:** from that end state, advance the main game with **on-policy
  play for all seats** until the explorer’s **next** *checkpoint* (or until
  they must act and we apply **one** on-policy move if you want a single
  plied), then **record** again.
- **Layer 2:** one more such cycle, **record** again, then **truncate** the side
  branch (do not play to the end of the game on that clone).

**Cap:** at most **two explorer-side decision layers** after the fork, i.e. two
*recordings* of state/score *after* the initial alternative (or: three total
*snapshots* on the branch: after alt, after first explorer follow-up, after
second — the parsing doc names these `layer` 0, 1, 2).

(Adjust naming in code: “round” in conversation = *explorer* depth on the
side tree, not “everyone played once around the table”.)

**Timer:** the main stem’s simulation is **one** pass; each fork only adds
short-lived clone work, bounded by the number of legals times the small depth,
so wall time is tractable.

## How much does it cost? (order of magnitude — not a full 04-1 run)

The 04-1 *collector* is not implemented yet, so this is **not** an end-to-end
timing of layer-0/1/2.  It **is** a one-game **counter** (same policy as
`04_decision_tree.run_single_pass`, same “real checkpoint” / single
match+pass rule) plus a **very loose** scale from the 04 DFS **clone** cost
(~0.18 ms per `copy.deepcopy` of `RlPick14State` in that experiment).

| Setup | On-policy **stem** only (one game, seed 42) | Explorer **F** = forks (real checkpoint & explorer to act) | **ΣK** = sum of `len(legal_moves)` at those forks | ΣK×3 = score-layer *endpoints* (3 layers × K branches) |
|-------|---------------------------------------------|----|--------|--------|
| 4p, n_hand=3, explorer=0 | **~1.6–2.0 ms** | **12** | **45** | **135** |
| 2p, same | **~1.2–1.9 ms** | **21** | **73** | **219** |

**Naive lower bound (wrong but informative):** if the only extra work were **ΣK**
full-state deep copies for layer-0 only (no on-policy sim on the clone, no
layers 1–2), the add-on would be about **ΣK × 0.18 ms** → **~8 ms** (4p) or
**~13 ms** (2p) **on top of** the ~2 ms stem — i.e. in the **~5–10×** range vs
stem for that one seed, **before** the real 04-1 work (roll each clone
forward to layers 1 and 2).  A realistic 04-1 run will be **higher** than
that lower bound, but still **not** the astronomical cost of 04’s full DFS.

So: **not** “double the time” in this sample — more like **several times** the
stem for one seat, unless code avoids full `deepcopy` (undo stack, or lighter
state).  It is also **not** 3 ms total unless you only measure a tiny subset;
the stem alone is already ~2 ms for 4p on this machine.

*Reproduce:* `python scripts/04-1_count_explorer_forks.py` (options for
`--n-players`, `--seed`, `--explorer`).

## What to record (for a future “good decision” rule — **not** implemented yet)

For each `ForkEvent` and each **branch** (stem + alternatives), at each **layer** `k`:

- Identifiers: game seed, step index, phase (`match` / `play`), which legal move
  (id / encoding).
- **Per-player** total **score** (sum of `score_pile` points as in
  `sim_core`), and/or the **N+1-style gap** used in 03-3 (points vs table
  mean at a chosen horizon) — the exact outcome column can be one field with a
  versioned name.

- **Comparison** (future): e.g. branch gap vs **stem** gap at the *same* layer
  to see if the stem was “locally” good.  *Do not* implement the comparison
  logic in the first pass; only make sure the **rows** are there.

See `parsing/04-1.md` for the exact record shape and `schema_version`.

- 04-1 = **sampled, bounded** off-policy shavings only for one seat — feasible.
