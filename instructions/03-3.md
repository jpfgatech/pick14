# Study of basic Q evaluation based on Card digit-appearence key

## Background

Previous test in 03-1.md has suggested that
- 20k games creates 666k keys, 33 per game
- Most keys are never repeated. Data density does not support per-key analysis at all

The aggregation in 03-2.md is not good enough either

In this attempt, we try to translate the raw snapshot into a feature exposed expression
The ultimate goal is that, we project the sparse states onto some meaningful manifold
And state projected to approxity of manifold, should also have similar Q values

## Math Model

We try to use a common vector to translate the states
In a post match, post play action, we have at most 3 hand cards
Together there are up to 7 different combination sets

We have many rows, each of 7 columns + 1 summary column

### Row of column validness
- To make a valid column, there must be a corresponding unique sum
- E.g. a hand of A/2/3 has 7 unique sums, thus 7 valid columsn, plus one summary column
- E.g. a hand of 4/4/5 has 4 unique sums: 4/5/4+5=9/4+4+5=13, thus 4 valid columns
- E.g. a hand of 4/4/4 has 3 unique sums: 4/8/12, thus 3 valid columns
- Mark valid/invalid with 1/0; the summary column denotes the total number of valid columns, normalized by max 7 to cap at 1.0

### Row of unique sum
- For a valid column, denote its sum in this row, normalize by 14
- e.g. A/2/3 would have 1/2/3/4/5/6/7 divided by 14 on this row
- the variable could exceed 1.0, max of K/K/K, 39/14
- the invalid columns should be filled with some garbage number, lets say 5 for now
- the summary column denotes the number unique sums < 14, normalized by max 7

### Known Catagory
- For a valid column
- If 14 - unique sum is present in the public pool, it is a valid and known match catagory
- Mark valid and known catagory with 1 and others with zero
- Put normalized sum in summary column
- (there is a redefinition here, A+4 would be the same catagory as 5 matching a 9)
- (we will consider if we should unfold this strategic space later. this is a note for human reader not the agent)

### Potential Catagory
- If 14 - unique sum is positive but does not present, it is a valid and potential catagory
- If 14 - unique sum is zero or negative, it is not a valid catagory
- Notice that known catagory is also a potential catagory but not vice versa
- Mark valid and potential catagory with 1 and others with zero
- Put normalized sum in summary column

### Number of options
- For a known category, count **occ** = how many public cards of the complement
  (14 − unique sum) appear in the public digit key.
- **Column value** = `occ / 4` for *every* complement, including when the
  complement is game value 5 (no alternate divisor 6 in code — that is the only
  meaning of “no special case for 5” here: **no special handling in
  implementation**).
- **Not** a clamp: do **not** use `min(occ, 4) / 4` unless you explicitly want to
  cap.  A fixed /4 is the *scale* for “per rank, four copies in the deck” for
  c ≠ 5.  For c = 5, the key combines five-rank cards and jokers (up to **six**
  physical cards); **necessarily**, `occ/4` can be > 1.0 on that row only if
  **occ ≥ 5** in public (e.g. 1.25 or 1.5).  That is normal deck geometry, not
  an optional “edge” story.
- **Summary column:** sum of the column values (over known categories) **divided
  by 7** like the other “normalized sum” rows.  The summary can pass 1.0 when
  many columns or high `occ` line up; that is acceptable.

### Max points
(point status is not recorded in the 03-1.md simulation. we need resimulation)
- For a known catagory, count the max possible points of it
- If there are multiple hand card combinations, count the max version
- E.g. Joker wins over 5H, count 5 points
- E.g. AH + 4H wins over Joker, count 8 points
- Add max hand card set points with the max public pool card points
- E.g. 9H wins over 9S, count 4 points
- For a state of AH+4H+Joker with 9H/9S in public
- The known catagory of unique sum of 5 matching public 9 would be 12 points
- Normalize the max points by max possible, 5+5+4+4 = 18 to cap at 1.0
- Put highest value in summary column

### Second points
- Based on max points
- If there is more than one public card present
- Replace the point of the highest public card with the second public card in the formula
- E.g. in the above example, replace 9H with 9S to derive 11 points, normalized by 18
- However, if there is not a backup public card, e.g. 9H only without any other 9
- Then the second points would be zero
- Put highest value in summary column


## Analysis and Expectations

We now have several different summary metrics
We plot the outcome of the state (use N+1 turn point gap as the single outcome metric)
against each summary metrics

Hopefully we should see strong correlation and not so big variation
Scatter plots of 666k scatters could be too heavy
Lets do an average curve along with quartile and extrema dash lines

Also, plot the frequency as curve or histogram, so that we recognize which data are reliable or not.

**Implementation (current `scripts/03-3_q_feature_analysis.py`).**  The spec above
uses **normalized** “summary” language (/7, /18) for the conceptual manifold; the
analysis code stores **raw** integer counts, raw f5, and **raw** score points
(0‥18) for f6/f7 so that scaling errors are easy to see.  Plots have **one
point per distinct feature value** (no width binning) plus a **frequency** panel
and a **per–snapshot-kind** copy of the gap curves.  The three **analysis**
kinds are: A (match), A (pass), and B (play) = B1 ∪ B2.  See `parsing/03-3.md`
for the exact artifact list.

## Findings

Setup: 20k games, 4-player, GFP match + caution play.  Pre-deck-draw snapshots
(deferred-draw API).  Features from actual `Card` objects.  **1,035,869**
retained N+1 samples.  **~1.50 ms/game**.

**Per-kind sample counts (not disjoint turn types — B merges B1 and B2):**
A (match) **389,281** · A (pass) **162,259** · B (play) **484,329**.

### Feature ranges (raw; f1‥f4 in 0‥7 for typical 3-card hands, f5 unbounded, f6‥f7 in score pts 0‥18)

| Feature | min | max | mean | Pearson r (N+1 gap) |
|---------|-----|-----|------|---------------------|
| f1  distinct subset-sums        | 0 | 7 | 4.24 | +0.022 |
| f2  distinct sums < 14          | 0 | 7 | 3.24 | +0.191 |
| f3  known match categories     | 0 | 7 | 0.61 | +0.248 |
| f4  = f2 (potential)              | 0 | 7 | 3.24 | +0.191 |
| f5  Σ(occ/4) over known           | 0 | 3.75 | 0.20 | +0.244 |
| **f6  hand + best pub (pts)**     | 0 | **18** | 2.22 | **+0.283** |
| f7  hand + 2nd pub (pts)          | 0 | 15 | 0.59 | +0.204 |

### Key observations

- **f6 (max raw match score)** still has the highest Pearson r (**+0.283**);
  the signal is the same in direction as the earlier /18-normalized run, but
  the **mean gap vs smallest vs largest distinct f6** in the new discrete summary
  is a different number than the old binned “bin delta” (no artificial bins
  any more).

- **f7** keeps similar r (**+0.204**).  The observed f7 max of **15** (not 18)
  reflects the **second**-best public in each category, not a bug.

- **f1** remains almost uncorrelated (r = +0.022).  **f2/f3/f5** sit near +0.19‥+0.25;
  the mix of A vs B in `features.png` and the per-kind figure show **where** each
  level of f2/f3 is concentrated, which a single pooled curve used to hide.

- **Frequency plot** (`feature_frequencies.png`) is essential for f3/f5: many
  states sit on **zero** or one known category, so the ends of the gap curves
  should be read together with the bar heights.
