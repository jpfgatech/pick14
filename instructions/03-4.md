# Study of basic Q evaluation based on Card digit-appearence key

## Background

The features extracted in 03-3.md shows some correlation, but not much
We run some more linear reversion to evaluate the data

## Math Model

In 03-4 we use 13 sum slots (game_value subset sums **s = 1 … 13**).

### Regression targets (own score, not point gap)

The linear model predicts the **current player’s own** match **points** on the
**next** match turn (N+1) and the **following** match turn (N+2).  We do **not**
use the table point-gap: the feature vector has no opponent *state*, so the
target should not depend on others’ scores for the same horizon.

### Model A — 13 × 2 + 1 unknowns

For each **s**:

- **x1[s]** — **Max** `score_value` sum over all non-empty hand subsets whose
  `game_value` sum equals **s**.  (0 if no such subset.)

- **x2[s]** — Occurrence structure: let **k** = number of distinct hand subsets
  (same hand, different index sets) with sum **s**.  Use **0** if k ≤ 1, and
  **2 × (k − 1)** for each extra combination (so scale is mixed with points
  only through the separate x1 channel).

- **Bias** — constant 1 (intercept).

### Model B — 13 × 4 + 1 unknowns

Same **x1**, **x2** as Model A.

For each **s** with a possible 14-sum match (complement **c = 14 − s** in
1…13), **known category** means: a hand subset sums to **s** and the public pool
has at least one card of `game_value` **c**.

- **x3[s]** — **Category point** for the best public target: **(max hand score
  for sum s) + (best public `score_value` among cards of game_value c)**.  0 if
  not a known category.

- **x4[s]** — **Category point** using the **second**-best public card of
  `game_value` **c** (same max hand score for sum **s**): max hand + 2nd pub
  score.  **0** if there is no second public card of that complement (no backup
  target).

### Fit and reports

Ordinary least squares.  Report R², RMSE, and per-coefficient values for each of
Model A / B and horizons N+1 / N+2.  The default simulation uses a **2-player**
table; coefficient plots are **curves of β vs. s** (separate line per feature
**type** x1, x2, …) plus a horizontal line for the **bias** (intercept).

## Findings

Setup: 20k games, **2p** (default), n_hand=3, seed=0. Pre-draw snapshots (same
simulation as 03-3). OLS via `numpy.linalg.lstsq`. Details: `parsing/03-4.md`.
Implementation: `scripts/03-4_linear_regression.py`.

### R² summary (targets = own next / next+1 **match** score, points)

| Model | Horizon | n | R² | RMSE |
|-------|---------|---|-----|------|
| A (27 feat) | N+1 | 1,089,236 | **0.1413** | 2.930 |
| A | N+2 | 1,033,517 | 0.0360 | 3.065 |
| B (53 feat) | N+1 | 1,089,236 | **0.1930** | 2.840 |
| B | N+2 | 1,033,517 | 0.0376 | 3.062 |

### Key observations

- **Own score (not point gap)** is the right target for hand+public features:
  the linear fit is nontrivial at N+1 (e.g. Model A **0.14** in this 2p run;
  4p runs are higher in absolute R² with more data diversity).

- **x1[s=1..4] stay the strongest positive predictors** of next own score; **x2**
  at low **s** is often **negative** (extra combinatorial multiplicity at the
  same sum is entangled with redundant ways to hit small sums).

- **Model B** improves N+1 R² to **0.19** here once **x3/x4** encode full
  **category** totals (hand + pub) — e.g. high-**s** x3 and paired x4 terms are
  visible on the **coefficient curves** vs. **s**.

- **N+2** remains weak (R² ≈ 0.04): two match turns ahead is hard to predict
  from a single snapshot.
