# A Direct Q function approach

I have decided to move to a direct Q function approach to crack the pick14 game

## Q function network

### Interface of the Q function network

- The Q function network takes a projected game state and evaluate its quality as a single scalar
- It relies on the environment to give it a list of projected states for valid actions of the current state
- The quality of each projected states will be converted to action probability through softmax
- The softmax is governed by a tau parameter

### State of the game

A round would be:

[init state] -> pass & play  -> [post play state]  -> draw to refill to 3   -> [post draw state] (randomness) -> init state for the next player
[init state] -> match        -> [post match state] -> draw to refill to 3+1 -> [post draw state] (randomness) -> play -> [post play state] -> init state for the next player

there are two chains, 6 total states
the initial state is the starting point of the round
the post play (two of them) and the post match states are the states to be projected for an action, i.e. Q network inputs theoretically
the post draw states are dominated by luck

### Generalized State by Random Draw and Averaging

However, we would like to simplify the states as such
For a pass & play action, the simulator generates not a single post play state, but a post draw state, traversing all possible cards to be drawn.
The Q network will be computed for each of the possible states, and the average of them will be taken as the quality of the pass action, to be compared against match actions
For a play action after a match, the simulator generates one state for each possible action for Q network to evaluate

Match action is harder
For a match action, the simulator generates not a single post match state, but a post play state, the final state
Suppose after a match action, the player has N cards in hand, and after refill and play, the player should have M cards in hand.
(Typically M = 3, except upon exhausted deck M could be fewer)
Suppose there are K cards remaining in deck. then the possible composition of a post play card is
- keep all N cards from hand, and take M-N from deck
- discard one of N cards from hand, and take M-N+1 from deck
- In other words, refill to M+1 cards with equal probability
- Then, test discarding one of the cards from M+1, and keep the version with highest Q among them (choose to play)
- Then, take the average of the preserved play outcome of the equally probable refill to M+1 card branch, as the projected quality of the match action
- For simplicity, lets cap the number of draw branches to be tested at 8

By such, the Q network is always executed upon an end-of-the-round state, and state marker is not required.

This is pretty complicated, so start with a printed log to verify the process, you me both.

### Output and training target of the Q network

The Q network predicts **future competitive advantage** only — **not** points captured on the immediate MATCH phase:

- At inference, realized match score enters action logits separately (`immediate_pts` in `direct_q`), then combines with `PickQNet`’s projected scalar on generalized states.

**Turn indexing (documentation)** — chronological steps \(j = 0,1,\ldots\) alternate seats as `(round r, seat s)` like `(0,0),(0,1),(1,0),(1,1),(2,0),\ldots`. Each stored sample has `chrono_index == j`.

**Pairwise gap** — synchronized rounds for two seats with ordinal \(t\) within each seat:

\[
\text{gap}[j] = \delta_{\text{seat}(j)}(t) - \frac{\delta_{\text{seat}(j)}(t) + \delta_{\text{opp}}(t)}{2}
\]

where \(\delta\) is the score–pile gain on that **full turn** (encoded as `score_delta` after the turn resolves).

**Supervised scalar (`q_target`) — future-only, finite horizon**

Immediate-turn gap \(\text{gap}[j]\) is **excluded** from the regression target so that e.g. when seat 0 scores +7 from A♦+5♦ vs 8♠ at chron `(0,0)`, those seven points never appear in `q_target` for that sample — only gaps from subsequent turns contribute.

With discount \(\gamma = 0.9\) (constant `GAMMA` in code):

\[
q_j = \sum_{h=1}^{H_j} \gamma^{\,h}\, \text{gap}[j+h],
\quad
H_j = \min(H_{\max},\, N - 1 - j).
\]

Default **`H_{\max} = 4`** (`Q_TARGET_HORIZON_TURNS`): up to **four following chronological turns** (≈ **two full alternating rounds** after the acting step). Not discounted to game end.

Rollout scripts still tabulate \(\delta\) per turn for auxiliary bookkeeping (`score_delta_match` records capture-from-match portions only — useful for diagnostics; targets use chronological horizon gaps as above).


### State Representation

We focus on a 2 player game
We use 54 cards x N channels to describe the status of the cards

For each turn, we record the score pile of the player and the public pool status at the end of the round.
We stack 3 turns for each player, and 2 players, taking 12 channels
The opponent and agent are placed in fixed position

The hand card of the agent is recorded with one channel

Then, the property of each card is recorded by 14 channels, 13 one hot channels for the digit, and a scalar channel for the points, 1 to 5. These are fixed

Thus a total of 12 + 1 + 14 = 27 channels

### Latent Space

The 27 channels are first projected to a 32 dimensional latent space
So the input to the core network becomes 54x32

### Attention Layers

We stack several attention layers
For each layer, we compute the self attention transform on the 54x32 input, followed by a feed forward network expanding to 128 (standard 4x) and shrink back, with 4 attention heads

### Q head

We collapse the 32 channels into 1 by 32 weights, averaging, followed by a 54 -> 128 -> 1 MCP network with ReLU activation and bias

### Opponent Hand Guessing Head

again collapse the 32 channels into 1 by another 32 weights. The output is considered as the exponential probability of the opponents' hand card status

### Training

We start with 2 Attention Layers. A game should generate roughly a dozen of states per seat; scale batch and epoch accordingly.

**Logging:** `scripts/05_train_timed.py` prints **``tr_q``** (mean per-batch Q-MSE during shuffled training), **``val_q``** (global validation MSE over the held-out 10%), **``tr_rmse``** / **``val_rmse``** (= √MSE), and **``val_cv``** (coefficient of variation of **``val_q``** over the trailing stability window — not sample-wise variance within one epoch). Use **`--epochs N`** for a fixed-length run (disables early stability stop); **`--rollout-dir`** loads shards from **`05_rollout_mass.py`**.

### Regularization — dropout

Use dropout in the transformer blocks (attention + feed-forward path) at a modest rate (default **p = 0.1**). Apply an additional dropout after the ReLU in the Q-head MLP (before the final linear to scalar **Q**). Training keeps dropout active; evaluation disables it via `eval()` mode.

### Rollout exploration (ε vs greedy baseline)

During simulated self-play rollouts used for targets / data collection, **do not** rely on a pure greedy baseline. At **each** decision point where the simulator chooses among legal moves — **MATCH** (including pass), and **PLAY** after match or pass — independently flip a coin with probability **ε** (default **25%**). If exploration triggers, pick **uniformly at random** among legal moves at that step; otherwise use the greedy baseline (same scoring tie-breaks as today). Overlap between the random pick and the greedy move is allowed.

Set **ε = 0** to recover purely greedy rollout.

### Mass rollout scale (comparison across exploration noise)

To compare outcomes under the **same deck** but different exploration RNG streams, simulate:

- **10 000** distinct deck configurations (`Random(deck_seed)` → deal / shuffle).
- **8** repetitions per deck — same shuffle, independent exploration RNG per repetition.

That yields **80 000** games total. See `scripts/05_rollout_mass.py` (`--deck-configs`, `--reps-per-deck`, `--explore-frac`).
